# Program-Activity State Build Spec (batch: full states)

This file is the single source of truth for building ONE new state's
program-activity module. Read it together with the reference implementation
`FY2025/program_activity/build_pa_program_activity.py` and its output
`docs/pa_program_activity.json` — mirror that exact style.

## What you must produce (3 artifacts)

1. `FY2025/program_activity/build_{abbr}_program_activity.py` — the build script.
2. `docs/{abbr}_program_activity.json` — generated by RUNNING the script.
3. `FY2025/program_activity/i18n_specs/{abbr}.json` — i18n + STATE_CONFIGS spec
   for the central merge step (do NOT edit docs/index.html or
   docs/program_activity.js yourself; those are merged centrally to avoid
   parallel-write conflicts).

`{abbr}` is the lowercase 2-letter state abbreviation (ut, az, nh, or, ri, in,
me, ar, ga). Prefix = same lowercase abbr.

## Output JSON schema (exactly this shape)

Top level is a single-key object keyed by the UPPERCASE abbr:

```json
{
  "UT": {
    "hfa_name": "Utah Housing Corporation",
    "hfa_abbr": "Utah Housing",
    "fiscal_year": "FY2025",              // honest: use "CY2025" for calendar-year sources
    "source_title": "...human-readable...",
    "source_url": "https://...",
    "source_file": "...filename(s)...",
    "retrieved": "2026-08-16",            // a fixed date string, never a live timestamp
    "categories": [ ... ],
    "projects": [ ... ]                   // [] is allowed only if genuinely no project list
  }
}
```

Category object:

```json
{
  "key": "multifamily_lihtc",
  "unit_type": "units",                  // "units" | "households" | "dollars"
  "fy2025_actual": 1666,                 // headline number; null for dollar-only categories
  "fy2025_source_quote": "\"...verbatim quote + page/doc ref...\"",
  "fy2025_amounts": [ { "label_key": "ut_amt_lihtc", "amount": 303200000 } ],
  "additive": false,                     // true only if subprograms are a true partition
  "fy2026": { "value": null, "amount": null, "closed": false, "note_key": "utFy26NotePending" },
  "subprograms": [
    {
      "key": "lihtc",
      "fy2025_units": 1666,              // null if dollar-only
      "fy2025_amount": 303200000,        // null if not disclosed
      "color_group": "credit",           // one of: bond | credit | trust | capital
      "fund_type": "proprietary",        // governmental | proprietary | off_balance_sheet | mixed
      "fund_name": "...",                // may be null
      "fy2026": { "value": null, "amount": null, "closed": false, "note_key": "utFy26NotePending" }
    }

```

Project object (only for states with a complete project list):

```json

  "name": "Project Name",
  "address": null,                       // null if source gives no street address
  "city": "Salt Lake City",
  "lat": 40.7608, "lon": -111.8910,      // round 5 dp; null if unresolvable
  "units": 72,
  "funding_sources": ["lihtc"],          // subprogram keys from the map category
```

## Build-script requirements

- Mirror `build_pa_program_activity.py` structure: a module docstring, `CATEGORIES`,
  `RAW_PROJECTS` (+ any `PROJECT_SOURCE_AMOUNTS`/`EXPECTED_*` helpers), a
  `verify_*` function that hard-errors on mismatch, a Nominatim `geocode()`
  (self-throttled 1 req/s, identifying User-Agent, cache, city-center fallback),
  and `main()` that runs verification → geocoding → writes JSON.
- **Dual verification gate is mandatory.** The transcribed unit/dollar sums must
  reproduce the source document's own printed totals (internal), and where a
  second independent number exists (press release headline, etc.) check against
  it too (external). If the source prints no totals, compute the column sums
  yourself once and assert against them (PA's Map Doc pattern).
- **Never fabricate.** If a figure isn't in the source, leave it null and say so
  in the docstring/quote. "not_feasible"-style gaps are honest results.
- **Year discipline.** A title's year is not proof of content year — verify by
  reading the actual sentence (project has hit this repeatedly). Exclude
  "since inception"/cumulative figures from any `fy2025_*` value.
- **Dollars without a paired unit/household count are not a KPI category** — a
  dollar-only line is at most an `fy2025_amounts` reference chip.
- **fund_type classification**: cross-reference the state's own ACFR text
  (`FY2025/txt/{ABBR}_..._FY2025_ACFR.txt`) like PA/VA do. Most HFAs are
  business-type/proprietary only. LIHTC/state-tax-credit allocations are
  `off_balance_sheet` (credits flow to developers, not booked as HFA assets).
  If the local txt is a wrong document (see your per-state brief), either use the
  correct PDF or classify conservatively by program description and document the
  confidence — do NOT invent a fund structure.
- Record `retrieved` as a fixed date string.

## Geocoding

- City-level source lists (most of this batch) → query `"{city}, {ST}"`, expect
  `geocode_status: "city_center"`. Street-address lists → `"{address}, {city}, {ST}"`
  with fallback to city. Honestly reflect precision; never claim `ok` for a
  city-center guess.
- If the source's own data has coordinates (rare), use them and mark `"official"`.

## i18n + config spec file format

`FY2025/program_activity/i18n_specs/{abbr}.json`:

```json
{
  "abbr": "UT",
  "prefix": "ut",
  "config": {
    "file": "ut_program_activity.json",
    "prefix": "ut",
    "modalTitleKey": "utModalTitle",
    "mapCenter": [40.0, -111.5],
    "mapZoom": 7
  },
  "i18n": {
    "zh": { "utModalTitle": "...", "utCat_multifamily_lihtc": "...", "utSub_lihtc": "...", "ut_amt_lihtc": "..." },
    "en": { ...same keys... },
    "es": { ...same keys... },
    "pl": { ...same keys... }
  }
}
```

The i18n keys are EXACTLY, for every language:
- `{prefix}ModalTitle`
- `{prefix}Cat_{category.key}` for each category
- `{prefix}Sub_{subprogram.key}` for each subprogram
- `{prefix}_amt_{fy2025_amounts[].label_key}` for each amount label

No other keys. `note_key` (`{prefix}Fy26NotePending`) is carried in the JSON but
the frontend does NOT read it, so it needs no i18n string. `mapCenter`/`mapZoom`
frame the state's bubble map (pick sensible state-centered coords/zoom like the
existing STATE_CONFIGS entries).

## Translations

- `ModalTitle` format mirrors existing entries, e.g. EN "Utah Housing FY2025
  Program Activity", ZH "犹他州 Utah Housing FY2025 项目活动". Follow the style
  of the existing `paModalTitle`/`ilModalTitle` strings in docs/index.html.
- Translate category/subprogram/amount labels accurately and idiomatically in all
  four languages (en/zh/es/pl). Keep agency/program proper nouns (LIHTC, HOME,
  HTF, program brand names) as-is where appropriate, same as existing entries.

## Final verification (run before declaring done)

1. `python FY2025/program_activity/build_{abbr}_program_activity.py` exits 0 and
   writes `docs/{abbr}_program_activity.json`.
2. Re-run it; the JSON should be byte-identical (geocoding cache makes it stable
   within a run).
3. Confirm every `cat.key`/`subprogram.key`/`label_key` in your JSON is present in
   your i18n_spec for all 4 languages (no missing, no extra).
