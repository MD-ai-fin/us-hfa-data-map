# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`us-hfa-data-map` (GitHub: `MD-ai-fin/ACFR`) is a bilingual (EN/中文) data-journalism project: it collects FY2024/FY2025 Annual Comprehensive Financial Reports (ACFRs) from all U.S. state Housing Finance Agencies (HFAs), extracts standardized financial metrics, enriches them with U.S. government open data (Census, BEA, BLS, HUD), and publishes the result as an interactive Leaflet.js map. There is no build tool, no test framework, and no linter — this is a Python/Node.js data pipeline that produces static JSON/HTML consumed by a hand-written vanilla-JS frontend.

## Common Commands

- **Local preview**: run `docs/serve.bat` (equivalent to `python -m http.server 8080` from `docs/`), then open `http://localhost:8080/index.html`.
- **Rebuild the main map dataset**: `python build_map_data.py` — merges all metric/enrichment sources and writes `docs/state_data.json`.
- **Re-run FY2025 collection/analysis** (per `FY2025/README.txt`): `python FY2025/collect_and_analyze.py` then `python FY2025/reextract_and_report.py`.
- **Rebuild per-state report/PDF links**: `node docs/_rebuild_links.js` — regenerates `docs/hfa_report_links.json` and cleans dead links.
- **Export analysis reports to HTML**: `python docs/export_reports.py` — converts the FY2025 Word reports to `docs/reports/fy2025-en.html` / `fy2025-zh.html` via `mammoth`.
- **Export analysis reports to accessible PDF** (Windows + local MS Word only): (1) `python docs/generate_report_docx_i18n.py` — rebuilds `FY2025/FY2025_US_State_HFA_ACFR_Analysis_Report_ES.docx` / `_PL.docx` from the translated HTML (ES/PL have no hand-authored .docx source, unlike EN/ZH); (2) `powershell -File docs/generate_report_pdfs.ps1` — drives Word via COM automation (`ExportAsFixedFormat` with `DocStructureTags`) to write tagged PDFs to `docs/reports/fy2025-{en,zh,es,pl}.pdf`, one Word instance per language (looping inside a single shared instance was unreliable); (3) `python docs/postprocess_report_pdfs.py` — patches in `/Title` and the correct `/Lang` via `pikepdf` (Word's COM automation doesn't set these reliably here) and prints a basic tagging sanity report. Re-run all three after the underlying report content changes. `docs/index.html`'s report modal links to these via `reportPdfPath()`.
- **Lease/SBITA and Gov-Wide SNP side-reports**: `node build_lease_sbita_report.js`, `node generate_lease_sbita_outputs.js` (or the `.ps1` equivalent), `node generate_gov_wide_snp_list.js`.
- **No tests, no lint, no CI**: `package.json`'s `test` script is the unmodified npm-init placeholder (`echo "Error: no test specified" && exit 1`); there is no `.github/workflows`, `tsconfig.json`, or bundler config. Deployment is implicit GitHub Pages serving the `docs/` folder on push to the default branch — no explicit workflow file.

## Architecture: the data pipeline

The site has no server and no framework; everything is precomputed into static JSON and read client-side. Stages, in order:

1. **Raw ACFRs**: `FY2024/pdf/` and `FY2025/pdf/` (gitignored, must be re-downloaded) with extracted plain text committed in the matching `FY2024/txt/` / `FY2025/txt/`.
2. **Download**: `download_fy2024_pdfs.js` (Node) for FY2024; `FY2025/collect_and_analyze.py` for FY2025, driven by `FY2025/direct_urls.json` and the agency directory `FY2025/state_hfa_catalog.json`.
3. **Extraction**: regex-based financial-figure extraction lives mainly in root `build_map_data.py` (`extract_hfa_pair`, `extract_component_unit_hfa`, `extract_hfa_mda_millions`, `extract_staff_from_acfr`, starting around `build_map_data.py:222`), plus `FY2025/reextract_and_report.py` / `summarize_metrics.py`. Output: `FY2024/fy2024_metrics.json`, `FY2025/fy2025_metrics.json`.
4. **Merge/enrich**: `build_map_data.py`'s `main()` (`build_map_data.py:1613`) is the single central aggregator. It combines both years' metrics with `hfa_staff_counts.json` (manually curated staff counts) and live-fetched Census population, BEA personal income, BLS unemployment, ACS poverty/home-price, and HUD homelessness point-in-time data (falling back to `web-map/homeless_pit_fallback.json` / `acs_fallback.json`, generated by `fetch_acs_fallback.py`, when a live source is unavailable). It writes the combined payload — including a `sources` dict documenting each metric's provenance — to **`docs/state_data.json`**, the app's single main dataset.
5. **Reports**: `docs/export_reports.py` converts the FY2025 Word analysis reports to `docs/reports/*.html`. `docs/generate_report_docx_i18n.py` + `docs/generate_report_pdfs.ps1` + `docs/postprocess_report_pdfs.py` produce accessible tagged PDF versions at `docs/reports/*.pdf`.
6. **Links**: `docs/_rebuild_links.js` maintains `docs/hfa_report_links.json` (per-agency web page / PDF links).
7. **Frontend**: `docs/index.html` (~2900 lines, single file, no `src/` layout) fetches three sources at runtime — `state_data.json`, the public US-states GeoJSON from `PublicaMundi/MappingAPI` (not stored locally), and `hfa_report_links.json` — and renders a Leaflet choropleth map, rankings, and detail drawers. `docs/play.js` (exposed via `window.initHfaPlay`) adds the "My State" / "Contrasts" interactive play modes and is called from `index.html`.

When changing what a financial metric means or how it's extracted, changes to the extractor functions in `build_map_data.py` usually need a matching change in the rendering logic in `docs/index.html` (e.g. `fmtDisplay`/`fmt`/`metricValueForState`, around `docs/index.html:1740`) — the two are not automatically kept in sync.

Two independent side-pipelines reuse the same `FY2024`/`FY2025` PDF/txt corpus but are unrelated to the map's data flow:
- Lease/SBITA liability extraction: `build_lease_sbita_report.js` → `lease_sbita_extracted_data.json` → `generate_lease_sbita_outputs.js`/`.ps1` → docx/xlsx report.
- Gov-Wide Statement of Net Position dual-column agency list: `generate_gov_wide_snp_list.js` → `Gov_Wide_SNP_Dual_Column_Agencies.xlsx`.
